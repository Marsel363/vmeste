# Бесплатное размещение «Вместе» для двух iPhone

Подготовлена версия 0.1.5: Python/FastAPI остаётся сервером, приложение устанавливается из Safari на экран «Домой». После размещения компьютер с PyCharm не должен постоянно работать.

**Состояние:** файлы и перенос данных подготовлены и проверены локально. Render и Neon пока не подключены; облачная база и публичная ссылка ещё не созданы. Проверка на самих iPhone выполняется после размещения.

## Выбранная схема

- **Render Free** — запускает Python-приложение, выдаёт адрес вида `https://имя.onrender.com` и HTTPS-сертификат. Покупать отдельный домен не требуется.
- **Neon Free** — отдельная постоянная PostgreSQL-база для аккаунтов, расписаний, заметок и правок.
- **GitHub** — хранит исходный код для сборки Render; можно использовать бесплатный приватный репозиторий.

Тарифы проверены 7 ноября 2026 года по официальным страницам: [Render Free](https://render.com/docs/free) и [Neon Free](https://neon.com/pricing). Neon указывает бесплатный план без срока пробного периода и без карты, с ограничениями по ресурсам. Render после 15 минут простоя останавливает бесплатный сервер; следующее открытие может занять около минуты. Приложение и база работают бесплатно в пределах лимитов этих планов.

Локальную SQLite-базу нельзя оставлять внутри бесплатного Render: файлы исчезают при остановке/перезапуске. В `render.yaml` поэтому предусмотрена внешняя база Neon. Бесплатная база самого Render не создаётся: она имеет срок 30 дней.

Не используется искусственный опрос сервера для предотвращения сна. Источники проверяются при открытии устаревшего расписания и пока сервер работает; фоновая проверка во время сна бесплатного сервера не выполняется.

## 1. Подключение аккаунтов

Для размещения через помощника установите Render и Neon и авторизуйтесь в своих аккаунтах. Если аккаунтов нет, создайте их на [Render](https://dashboard.render.com/) и [Neon](https://console.neon.tech/) с бесплатными планами. Не выбирайте платные дополнения.

Для сборки из исходников также понадобится репозиторий GitHub. Если его ещё нет, создайте бесплатный аккаунт на [GitHub](https://github.com/) и приватный репозиторий, например `vmeste`. При подключении репозитория Render запросит доступ через собственную страницу авторизации.

## 2. Обновление локального проекта перед переносом

1. Остановите сервер в PyCharm и сделайте резервную копию текущего проекта, особенно `.env` и `vmeste.db`.
2. Из архива 0.1.5 скопируйте в текущий проект папки `app`, `static`, `data` и файлы `Dockerfile`, `render.yaml`, `.dockerignore`. Свои `.env`, `vmeste.db` и `.venv` сохраните.
3. Для уже работающей версии 0.1.4 новые библиотеки не требуются. При необходимости установите имеющиеся зависимости командой:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

## 3. База Neon

Создайте проект `vmeste` на плане **Free**, регион Frankfurt, PostgreSQL. Дополнительные сервисы авторизации Neon для этого приложения не нужны — в нём уже есть свои два аккаунта.

В разделе подключения получите стандартную строку PostgreSQL с `sslmode=require`. Для первоначального переноса удобнее прямая строка подключения, без pooling. Сохраните её для ввода в Render и в локальную команду переноса. Не добавляйте её в исходный код или GitHub.

## 4. Перенос существующих аккаунтов и заметок

Перенос выполняется один раз в **пустую** целевую базу. На этом этапе старый сервер должен быть остановлен, чтобы никто не добавлял изменения во время переноса.

Из терминала **текущего проекта, где находится ваша рабочая vmeste.db**, выполните:

```powershell
.\.venv\Scripts\python.exe -m app.transfer_database --source .\vmeste.db
```

Команда попросит строку Neon. Вставьте её в терминал: ввод скрыт. Передаются все записи календаря, существующие логины, хэши паролей, код приглашения и заметки. Исходный SQLite-файл открывается только для чтения. Если целевая база уже содержит данные, команда откажется продолжать — не удалит и не перезапишет их.

После завершения будут выведены только количества записей. Сохраните резервную копию локального проекта. **Не создавайте новую пару на сервере:** в облаке нужно войти существующим логином и паролем.

SQL-перенос в реальный Neon будет проверен после подключения аккаунта. Локальные тесты уже проверили сохранность идентификаторов, паролей и заметок, неизменность исходного Windows-файла и отказ от перезаписи непустой базы.

## 5. Исходный код на GitHub

Загрузите содержимое папки `vmeste-pwa` из подготовленного архива в корень приватного репозитория. В корне должны быть видны `render.yaml`, `Dockerfile`, `requirements.txt`, папки `app`, `static` и `data`.

В подготовленном архиве нет вашей рабочей `.env`, `vmeste.db` и виртуального окружения. Их не следует добавлять в репозиторий; правила `.gitignore` и `.dockerignore` исключают эти файлы. Публичный PDF расписания и метаданные календаря находятся в `data` и нужны сборке.

## 6. Бесплатный сервер Render

В Render создайте **Blueprint** из этого репозитория. Файл `render.yaml` уже задаёт:

- Web Service на плане **Free**;
- сборку Docker с папкой `data`;
- автоматически сгенерированный постоянный `SECRET_KEY`;
- защищённые cookies;
- запрет посторонним создавать первую пару на пустом публичном сервере;
- внешний PostgreSQL вместо временного SQLite;
- один серверный процесс для совместных обновлений двух аккаунтов.

При создании Render запросит **DATABASE_URL** — вставьте строку своей базы Neon. Адрес приложения определяется автоматически через `RENDER_EXTERNAL_URL`; его не нужно заранее угадывать в настройках.

Дождитесь успешной сборки и состояния Live. Полученный HTTPS-адрес будет вашей общей ссылкой. Указанный в документе шаблон `имя.onrender.com` — пример, не готовая ссылка.

Если делаете настройку вручную вместо Blueprint: Docker, план Free; переменные `APP_ENV=production`, `COOKIE_SECURE=1`, `ALLOW_CREATE_COUPLE=0`, `FORWARDED_ALLOW_IPS=*`, `MGSU_SOURCE=auto`, постоянный случайный `SECRET_KEY` не короче 32 символов и `DATABASE_URL` из Neon. Значения из локального `.env` поверх этих серверных настроек не копируются.

## 7. Установка на оба iPhone

1. Откройте настоящую HTTPS-ссылку в **Safari** на первом iPhone.
2. Войдите своим существующим аккаунтом, проверьте расписание и заметки.
3. Нажмите **«Поделиться» → «На экран Домой»**. Если есть переключатель **«Открывать как веб-приложение»**, оставьте его включённым, затем нажмите **«Добавить»**.
4. Откройте «Вместе» появившимся значком. При необходимости войдите ещё раз.
5. На втором iPhone повторите шаги, войдя вторым аккаунтом. Если второй аккаунт ещё не создан, используйте существующий код приглашения из первого.

Инструкция также находится внутри приложения в разделе **Настройки → Установить на iPhone**. Публикация в App Store для этого способа установки не требуется. [Официальная инструкция Apple](https://support.apple.com/ru-ru/guide/iphone/iphea86e5236/ios).

## 8. Проверка после публикации

- Откройте приложение с мобильного интернета на обоих iPhone.
- Убедитесь, что прежние аккаунты и заметки сохранились.
- Измените заметку на одном телефоне и проверьте её появление на другом.
- Перезапустите/повторно разверните сервис Render и проверьте, что данные остались в Neon.
- После успешного открытия один раз включите авиарежим: должна быть доступна сохранённая копия расписания с отметкой отсутствия связи. Первое открытие без сети невозможно.
- После простоя дождитесь пробуждения бесплатного сервера. При превышении бесплатных лимитов сервисы могут приостановить работу до следующего периода — это ограничение хостинга, не удаление базы приложением.

Обновление PWA не перезагружает страницу принудительно во время редактирования заметки. После выпуска новой версии приложение можно закрыть и открыть снова. Офлайн доступен просмотр ранее загруженных данных; отправка правок требует связи.
